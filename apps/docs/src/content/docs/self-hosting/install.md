---
title: Установка VoiceRoom Meet на свой сервер
description: Как установить VoiceRoom Meet на Linux, настроить домен и провести первую временную видеовстречу.
---

VoiceRoom Meet подходит для временных видеовстреч. Владелец создаёт встречу, а гости присоединяются по ссылке и вводят свои имена.

## 1. Подготовьте сервер и домен

Понадобится Linux-сервер `x86_64` с публичным IPv4 и доступом к терминалу. На сервере должны быть `curl`, `openssl`, `jq`, `dig`, `ss` (из `iproute2`), `flock` (из `util-linux`) и `timeout` (из `coreutils`). Для запуска нужен Docker Engine с плагином `docker compose`, который поддерживает `up --wait`. Если Docker ещё не установлен, установщик предложит установить его официальным скриптом после подтверждения.

Откройте входящие порты в файрволе сервера и в панели хостинга. Они должны быть свободны на сервере.

| Порт | Для чего |
| --- | --- |
| `80/TCP` | HTTP и получение сертификатов |
| `443/TCP` | HTTPS, сигналинг LiveKit и TURN/TLS через Caddy |
| `7882/UDP`, `7881/TCP` | Прямая передача аудио и видео |
| `3478/UDP` | TURN по UDP |
| `30000–30099/UDP` | Порты ретрансляции медиа LiveKit |

Выберите домен для встречи. Meet использует это имя для страницы и сигналинга, а `turn.<домен>` — для ретранслятора. TURN включён по умолчанию. Если сеть участника блокирует прямые медиапорты, браузер может подключиться через TURN/TLS на `443/TCP`.

| Вариант | Что подготовить |
| --- | --- |
| DuckDNS (по умолчанию) | Создайте имя, например `my-meet.duckdns.org`, в личном кабинете [DuckDNS](https://www.duckdns.org/). При установке введите имя и токен DuckDNS. |
| deSEC | Зарегистрируйте имя вида `my-meet.dedyn.io` в [deSEC](https://desec.io/signup?domainType=dynDNS) и подготовьте токен API с доступом к A-записям основного имени и вложенного имени `turn`. |
| Свой домен | Создайте A-записи для домена Meet и TURN, например `meet.example.com` и `turn.meet.example.com`. Обе должны указывать на публичный IPv4 сервера. Если провайдер DNS предлагает проксирование трафика, выберите режим «только DNS». |

Для DuckDNS и deSEC установщик настроит DNS через API провайдера. Для любого варианта он проверит, что у каждого из двух имён одна A-запись на IPv4 сервера и нет AAAA-записи. Для DuckDNS можно указать вложенное имя, например `video.my-meet.duckdns.org`. Оно и `turn.video.my-meet.duckdns.org` используют IP-адрес зарегистрированного имени `my-meet.duckdns.org`. Домены `duckdns.org` и `dedyn.io` включены в [Public Suffix List](https://publicsuffix.org/list/).

## 2. Установите Meet

Запустите эту команду в терминале сервера от `root`.

```sh
curl -fsSL https://get.voiceroom.ru | sh
```

Из обычной учётной записи запустите `curl -fsSL https://get.voiceroom.ru | sudo sh`. Установщик задаёт вопросы через терминал даже при запуске через конвейер. Токен вводится без отображения. Если обе A-записи уже настроены, можно передать домен и провайдера аргументами.

```sh
curl -fsSL https://get.voiceroom.ru | sudo sh -s -- install --provider own --domain meet.example.com
```

Установщик скачивает комплект релиза, проверяет контрольные суммы и запускает Compose с образами, закреплёнными по дайджестам. Caddy автоматически получает сертификаты для имён Meet и TURN. После проверки готовности установщик выводит адрес Meet и одноразовую ссылку владельца. Ссылку владельца храните в секрете.

## 3. Проведите первую встречу

1. Откройте ссылку владельца, нажмите «Создать встречу» и скопируйте ссылку на встречу.
2. Откройте ссылку на встречу сами и отправьте её гостям. Каждый участник вводит имя и разрешает браузеру доступ к микрофону.
3. Проверьте звук в обе стороны. Если страница открывается, а звука нет, проверьте прямые медиапорты `7882/UDP` и `7881/TCP` из внешней сети. Для ретрансляции проверьте DNS имени `turn.<домен>` и доступность портов TURN из таблицы. Локальная проверка установщика не подтверждает доступность портов через файрвол или NAT.

## Управление сервером

| Команда | Действие |
| --- | --- |
| `sudo voiceroom install` | Повторно запустить установку с сохранением существующих секретов. |
| `sudo voiceroom status` | Проверить состояние сервера и посмотреть имя и порты TURN. |
| `sudo voiceroom upgrade` | Обновить до последнего релиза с комплектом Meet. Чтобы выбрать версию, передайте её тег как аргумент. |
| `sudo voiceroom domain show` | Посмотреть текущий домен. |
| `sudo voiceroom domain set` | Настроить домен заново или сменить его. Для своего домена подготовьте A-записи для двух новых имён. После смены используйте новый адрес Meet. |
| `sudo voiceroom owner-link` | Показать ссылку владельца, если она ещё не использована. |
| `sudo voiceroom owner-link --rotate` | Создать новую ссылку владельца и отозвать предыдущие ссылки и разрешения владельца. |

Перед обновлением установки без TURN откройте `3478/UDP` и `30000–30099/UDP` в файрволе сервера и в панели хостинга. Если вы используете свой домен, добавьте A-запись `turn.<домен>` на публичный IPv4 сервера. В DuckDNS имя TURN уже использует IP-адрес зарегистрированного имени.

Запустите обновление свежей версией установщика, чтобы проверить DNS и порты TURN. Если имя TURN в deSEC ещё не указывает на сервер, установщик запросит токен deSEC и настроит запись. Если запускаете обновление старой командой `voiceroom upgrade`, добавьте эту запись в deSEC заранее.

```sh
curl -fsSL https://get.voiceroom.ru | sudo sh -s -- upgrade
```

Планируйте обновление на время без встреч. Оно останавливает приём звонков до миграции. При сбое CLI восстанавливает предыдущий релиз. Сохраняйте `.env` в каталоге установки `/opt/voiceroom` и постоянные тома Docker, в том числе том владельца. Копии `.env` и манифеста релиза остаются в `/opt/voiceroom/backups`. В копии `.env` есть секреты, поэтому храните её так же, как оригинал.

## Что хранится на сервере

Во время встречи отображаемые имена находятся в памяти, а текст чата получают только подключённые к встрече участники. Сервер не записывает переписку, историю звонков, аналитику и замеры использования и не выполняет поиск по IP или геолокации. PostgreSQL временно хранит рабочие записи комнаты, идентификаторы участников с хешами токенов и данные допуска к LiveKit. Эти записи удаляются из таблиц при закрытии комнаты, а при старте удаляются записи оставшихся Meet-комнат.

Журналы стека не содержат имён участников, сообщений или токенов. Docker хранит до трёх файлов журнала по 10 МБ на контейнер. Для отката обновления CLI создаёт закрытую временную копию PostgreSQL и удаляет её после успешного обновления или отката. Если восстановление прервалось или завершилось с ошибкой, копия остаётся для следующей попытки. В ней могут быть рабочие записи, существовавшие на момент копирования. Срок хранения резервных копий, которые вы создаёте самостоятельно, задаёте вы.

Для аккаунтов, постоянных комнат, истории чатов и админки используйте [руководство по установке полного стека](https://github.com/dazeGG/VoiceRoom/blob/main/docs/SELF_HOSTING.md#установка-полного-стека).
