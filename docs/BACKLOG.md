# Backlog

## Полная декомпозиция legacy backend/frontend

**Статус:** не является gate release train 2.5.0–2.7.0. В этих релизах
архитектурные границы обязательны для каждого затронутого модуля, но полный
rewrite или механическое уменьшение файлов не выполняется.

После 2.7.0 направление планируется отдельно по измеренным hotspots:

- собрать ownership/cycle/deep-import отчёт после завершения messaging,
  notifications и media seams;
- выделять следующий модуль только при понятной границе данных, транзакций и
  runtime ownership;
- сначала зафиксировать поведение regression/contract tests;
- перенос кода и изменение поведения выпускать разными PR;
- не вводить новый deployable service без доказанной операционной потребности.

## Монетизация комнат: slugs и управляемые коды подключения

**Статус:** отложено до этапа монетизации и не входит в release train
2.5.0–2.7.0.

Планируемая модель:

- внутренний `roomId` остаётся неизменяемым идентификатором комнаты;
- текущий slug используется только как публичный адрес, но не как ключ доступа;
- по умолчанию комнате назначается случайный slug;
- платный подписчик может установить красивый или короткий slug;
- после смены старый slug 30 дней временно перенаправляет на новый, затем освобождается;
- после окончания подписки действует 30-дневный grace period, затем назначается случайный slug, а пользовательский освобождается;
- ссылка с кодом имеет вид `/r/?code=a8k2mqp7`; после погашения код сразу удаляется из URL;
- комната может иметь несколько кодов с отдельными сроками жизни, лимитами применений и возможностью отзыва;
- использование кода засчитывается только при успешном входе; reconnect и повторная вкладка не расходуют его снова;
- зарегистрированный пользователь после входа по коду становится участником комнаты;
- гость получает только временный доступ, не становится участником и не может быть упомянут через `@`;
- отзыв или истечение кода запрещает новые входы, но не отключает уже вошедших пользователей.

Перед реализацией потребуется отдельная модель entitlement/subscription и единая проверка доступа для voice, chat, preview, roster и LiveKit token.

## GIF в личных сообщениях и чате комнаты

**Статус:** отложено и не входит в release train 2.5.0–2.7.0. Отправка
обычных изображений запланирована отдельно в
[релизе 2.7.0](./RELEASE_2.7.0_PLAN.md).

Планируемое направление:

- добавить общий `GifProvider`, чтобы внешний сервис можно было заменить без изменения модели сообщений;
- первым кандидатом рассмотреть KLIPY, а GIPHY оставить запасным вариантом;
- перед реализацией повторно проверить production-условия, лимиты, стоимость, атрибуцию и правила хранения контента;
- сравнить качество выдачи провайдеров на русских и английских запросах;
- на десктопе открывать быстрый picker в popover с возможностью развернуть его в модальное окно;
- после появления мобильной версии использовать на телефонах полноэкранный picker;
- поддержать поиск, тренды, категории и недавние GIF;
- хранить в сообщении только провайдера и стабильный идентификатор GIF, не копируя внешний файл в наше хранилище;
- предусмотреть фильтрацию контента, обязательную атрибуцию и заглушку для удалённого или недоступного GIF.

Перед реализацией отдельно решить, отправляется ли выбранный GIF сразу или сначала добавляется в черновик сообщения.

## Мобильная версия и PWA

**Статус:** отложено и не входит в release train 2.5.0–2.7.0. До реализации
VoiceRoom остаётся desktop-only продуктом, а мобильные браузеры получают
заглушку из [плана 2.5.0](./RELEASE_2.5.0_PLAN.md).

Планируемое направление:

- спроектировать полноценный phone/tablet UX для landing, lobby, room, chat,
  DM, settings, membership и moderation вместо уменьшения desktop-интерфейса;
- отдельно адаптировать touch-навигацию, safe areas, portrait/landscape,
  экранную клавиатуру и mobile media permissions;
- проверить lifecycle voice/realtime при background/foreground и ограничения
  iOS/Android до обещания стабильных звонков;
- добавить Web App Manifest, PNG-иконки 192/512 и maskable-вариант,
  `display: standalone`, theme/background и корректный install flow;
- поддержать установку Android из браузера и понятную инструкцию «На экран
  Домой» для iOS;
- добавить управляемое обновление service worker с явным предложением
  перезагрузить новую версию;
- кешировать только app shell и versioned static assets;
- показывать offline-экран «Нет соединения»;
- сохранить Web Push и notification deep links;
- после подтверждения mobile readiness удалить desktop-only gate из app shell.

В первую версию PWA не входят offline voice/chat, offline-очередь сообщений и
фоновая синхронизация пользовательских действий.
