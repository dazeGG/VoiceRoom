# VoiceRoom 2.6.3 — логи из браузера можно включить

Релиз поверх 2.6.2, обратно совместимый. Миграций нет, схема не меняется, откат сводится к подмене тега образа.

Для пользователя не меняется ничего.

## Что было не так

В 2.6.2 приём логов из браузера описан в заметках и реализован в API, но переменная `CLIENT_LOG_INTAKE_ENABLED` не передавалась контейнеру: `docker-compose.yml` отдаёт окружение явным списком, и этих ключей в нём не было. Значит, включить приём в контейнерном развёртывании было нельзя ни на одном хосте — правка `.env` не дала бы ничего и никак бы об этом не сообщила.

## Исправлено

- `CLIENT_LOG_INTAKE_ENABLED`, `CLIENT_LOG_RATE_LIMIT` и `CLIENT_LOG_RATE_WINDOW_MS` проведены в сервис `api`. Умолчания совпадают с кодом, поэтому поведение не меняется, пока оператор не выставит флаг.
- Добавлена проверка инварианта: флаг, который API оставляет выключенным по умолчанию, недостижим, если compose его не передаёт. Тест называет пропущенный ключ и покрывает заодно `LINK_PREVIEWS_ENABLED` и `TRUST_PROXY`.

## Обновление

- Миграций нет.
- Новых переменных окружения нет: те же три ключа из 2.6.2, теперь действительно доезжающие до контейнера.
- Приём логов из браузера по-прежнему выключен по умолчанию. Чтобы включить на хосте, добавьте в `.env` строку `CLIENT_LOG_INTAKE_ENABLED=true` и пересоздайте контейнер `api`. Пока флага нет, `/api/client-logs` отвечает 404, и браузер перестаёт слать отчёты.
- Окно «Что нового» остаётся на 2.6.0: этот релиз его не переписывает.
- Контракт логирования целиком описан в `docs/LOGGING.md`.
