# VoiceRoom 2.6.4 — выход из звонка перестал писаться как ошибка

Хотфикс поверх 2.6.3, обратно совместимый. Миграций нет, схема не меняется, откат сводится к подмене тега образа.

Для пользователя не меняется ничего: звонки работали и до этого. Исправлен поток ошибок в логах.

## Что было не так

Каждый завершённый звонок писал в лог ошибку уровня 50 — по одной на каждого вышедшего участника:

```
evt: livekit.participant_remove_failed
err: twirp error unknown: participant does not exist (404, not_found)
```

Клиент отключается от SFU сам, поэтому к моменту серверной уборки участника там уже нет. Это и есть то состояние, которого добивается удаление, а не сбой.

Подавление этого случая в коде было, но сверялось только с текстом `error.message`, где написано «participant does not exist». Признак Not Found LiveKit кладёт в `name`, `code` и `status`, так что условие не срабатывало ни разу за всё время его существования.

Само по себе это не мешало звонкам, но делало новый поток ошибок бесполезным: любое оповещение по уровню 50 и выше срабатывало бы после каждого разговора.

## Исправлено

- Признак «участника уже нет» определяется по ошибке целиком: `status`, `code` и текст в `name`/`message`, а не по одному сообщению.
- Настоящий сбой удаления по-прежнему попадает в поток ошибок и теперь несёт `roomId` и `peerId`.
- Два теста на точном объекте ошибки из продакшена: распознавание уже ушедшего участника по каждому признаку в отдельности и сохранение ошибки при ответе 500, отказе в правах и пустом значении.

## Обновление

- Миграций нет.
- Новых переменных окружения нет.
- Окно «Что нового» остаётся на 2.6.0: этот релиз его не переписывает.
