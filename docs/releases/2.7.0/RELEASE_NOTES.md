# VoiceRoom 2.7.0 — голос, безопасность и переписанная основа

Релиз поверх 2.6.4. Большая часть работы внутри: бэкенд переведён на TypeScript, данные читаются через один слой, тесты проверяют поведение. Снаружи заметны улучшения голоса и исправления чата.

## Голос и демонстрация экрана

- Автоматическая чувствительность микрофона: порог гейта подстраивается под шум в комнате. Включается в «Настройки → Звук».
- В статусе звонка видны потери пакетов, джиттер и переход на TCP или relay, так что плохая связь отличима от тихого собеседника.
- Демонстрация экрана снова идёт в 60 FPS, кодеки подобраны под неё.
- Голоса собеседников играют на отдельном элементе, поэтому Chrome гасит эхо.
- Цепочка микрофона собирается в одном `AudioContext`.
- TURN/TLS на общем порту 443 для сетей, где закрыт UDP. Выключен по умолчанию, включается на хосте (`TURN_ENABLED`, `TURN_DOMAIN`, раздел «TURN» в `README.md`).

## Чат

- Правка сообщения в комнате показывает новый текст. Раньше на экране оставался старый, хотя стояла пометка «(изменено)».
- Следующее сообщение можно печатать и отправлять, пока предыдущее ещё уходит: сообщения идут по одному, в порядке отправки. Если отправка не удалась, текст возвращается в поле.
- Превью ссылки больше не теряется у собеседника, когда оно готово раньше самого сообщения.
- Escape закрывает панель уведомлений.
- Гость во вкладке «Участники» видит, что список доступен после входа, а не ошибку.
- Поля «Код комнаты» больше не вызывают подсказки менеджера паролей поверх списка комнат.
- Карточка профиля на ссылке комнаты открывается один раз, а не дважды.

## Безопасность

- Токен LiveKit привязан к пропуску гейта и живёт 10 минут; пропуск отзывается на сервере при кике, бане и выходе. В LiveKit попадают только участники из списка комнаты.
- Origin проверяется на каждой записи cookie и при открытии WebSocket.
- Неудачные входы ограничены и по аккаунту, а не только по адресу.
- Заблокированные не читают чат и список участников комнаты.
- Идентификаторы участников-аккаунтов зарезервированы, авторство сообщений привязано к аккаунту.
- Картинки превью ссылок декодируются только после проверки сигнатуры.
- Из браузерных логов вырезаются query-строки и токены; публичные маршруты не раскрывают внутренние детали.

## Основа

- API, воркеры, гейт, скрипты и тесты написаны на строгом TypeScript (Node 24, без шага сборки).
- Один пул PostgreSQL и Kysely с типами, сгенерированными из схемы; доменные репозитории вместо общих «сторов».
- Контракты HTTP и realtime лежат в `packages/shared` и общие для API и веба.
- Веб: состояние в классах на рунах, разбитые на части лобби, чат комнаты и клиент комнаты.
- Тесты вызывают код и рендерят компоненты, а не читают исходники; веб-тесты идут на Vitest. В проверку добавлены ESLint с типами и Prettier.
- Убран механизм готовности «capabilities» из 2.5: все функции просто включены. `GET /api/capabilities` остался для старых клиентов и отвечает `true` по всем ключам, `/api/healthz` отвечает `{ ok, livekit }`.
- Воркеры поднимаются после перезагрузки хоста (`restart: unless-stopped`), а после каждого развёртывания удаляются старые образы.

## Обновление

- **Одна миграция:** `20260929160000_drop_capability_runtime_heartbeats` удаляет таблицу `capability_runtime_heartbeats`, в которую больше никто не пишет.
- **Откат на 2.6.4:** сначала один раз `node apps/api/src/scripts/migrate.ts down` (воссоздаёт таблицу), затем подмена тега образа. Автооткат в `scripts/cd/remote-deploy.sh` миграции не откатывает; без таблицы 2.6.4 выключит функции, зависящие от воркеров.
- **Окружение:**
  - ключи `CAPABILITY_*` больше не читаются, их можно убрать из `.env` после выкатки;
  - `LIVEKIT_TOKEN_TTL_SECONDS` по умолчанию `600` (было `21600`); если в `.env` хоста задано старое значение, его стоит убрать;
  - новые необязательные: `LIVEKIT_GATE_CREDENTIAL_TTL_SECONDS` (`21600`), `TURN_ENABLED` (`false`), `TURN_DOMAIN`.
- Окно «Что нового» остаётся на 2.6.0: этот релиз его не переписывает.
