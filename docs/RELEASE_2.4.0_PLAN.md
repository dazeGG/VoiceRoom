# План релиза 2.4.0

Статус: утверждён (обсуждение 2026-07-10). База: `develop` @ 2.3.4.

Тема релиза: **социальный слой и контроль** — модерация комнат, удаление сообщений,
приглашение друзей в комнату (ring), Web Push и настройки уведомлений, плюс
приведение чата к современному минимуму (ссылки, многострочность).

## Зафиксированные продуктовые решения

| Вопрос | Решение |
| --- | --- |
| Причина кика/бана | Не указывается. Цель видит только «Вас исключили из комнаты» / «Вы заблокированы в этой комнате» |
| Срок бана | Перманентный. В схеме есть nullable `expires_at` на будущее, UI таймера нет |
| Разбан | Только через undo-тост сразу после бана. Списка «Заблокированные» в настройках комнаты нет (отложено до дискорд-лайк «серверов»); API-эндпоинт разбана существует (его дёргает undo) |
| Идентичность бана | Запись = `user_id` (если есть) + IP на момент бана; при входе проверяются **оба**. VPN-обход гостём — принятое ограничение (как у Discord/Telegram); настоящая защита — будущая приватность комнат |
| Скоуп модерации | Только статичные комнаты (временные ownerless по дизайну — модератора нет) |
| Удаление сообщений | Свои — в чате комнаты и в ЛС, без лимита времени. Владелец комнаты — любые сообщения в своей комнате. Сообщение **исчезает полностью** (без tombstone), в ЛС — у обеих сторон |
| Ring | Только изнутри комнаты, только друзьям. Фидбек отправителю минимальный («Приглашение отправлено»), отказ невидим. Эфемерный (~30 сек), журнала пропущенных нет |
| Push-события | Ring, личные сообщения, заявки в друзья (+принятие). Сообщения комнат и «друг в эфире» — нет |
| Доставка push | Сервер шлёт всегда; service worker на устройстве **подавляет** показ, если есть вкладка в фокусе (in-app тосты закрывают этот случай). Push только залогиненным |
| DND | Простой ручной тумблер (без таймера), серверное состояние, индикатор на аватаре |
| Mute треда ЛС | Есть, серверный (гасит push и звук), unread-бейдж остаётся |
| Mute комнаты | Только звуки на текущем устройстве → localStorage, работает и для гостей |
| Меншены | **Отложены** (2.5.0) |

Вне скоупа 2.4.0: меншены, реплаи, PWA-манифест, приватность комнат
(пароль/«постучаться»), аватарки, статусы presence, глобальный push-to-talk
(desktop-проект), UI списка банов.

## 1. Чат: кликабельные ссылки + многострочность

Касается чата комнаты (`RoomChat.svelte`) и ЛС (`DmView.svelte`) одинаково.

**Клиент:**
- Общий компонент/утилита линкификации в `apps/web/src/lib/shared/` —
  разбор текста на сегменты `текст | ссылка` на рендере, **без `{@html}`**
  (сохраняем автоэкранирование Svelte). Распознаём только `http(s)://…` и
  `www.…`; рендер `<a target="_blank" rel="noopener noreferrer nofollow">`.
- Композеры: `<input>` → авторастущий `<textarea>`; **Enter = отправить,
  Shift+Enter = перенос строки**. Лимит 500 символов сохраняется.
- Рендер текста: `white-space: pre-wrap`; при отправке больше не схлопывать
  `\s+` в один пробел (сейчас `RoomChat.svelte` делает `draft.replace(/\s+/g, ' ')` —
  убрать); нормализация: trim, 3+ пустых строк подряд → одна.

**API:** `cleanChatText` — сохранить переводы строк, ограничить число строк
(например ≤ 20), прочая валидация без изменений.

**Тесты:** unit на линкификатор (не-URL, урезание опасных схем `javascript:`),
API-тест на сохранение `\n`, обновление `v2-ui-contract.test.js`.

## 2. Удаление сообщений

**Миграции:**
- `room_messages`: + `author_user_id varchar(36)` nullable, FK → `users(id)`
  `ON DELETE SET NULL`. Заполняется при отправке залогиненным.
- `direct_messages`: + `deleted_at timestamptz`; пересоздать частичный индекс
  unread как `WHERE read_at IS NULL AND deleted_at IS NULL`; thread-индексы —
  аналогично исключить удалённые.

**API:**
- `DELETE /api/rooms/:roomId/chat/:messageId` — JSON-body `{peerId, sessionToken}`
  для гостей, cookie-сессия для залогиненных. Право: peer-сессия совпадает с
  `peer_id` сообщения, **или** `author_user_id` = текущий пользователь, **или**
  текущий пользователь — владелец комнаты (модерация).
- `DELETE /api/dm/:userId/messages/:messageId` — cookie-сессия; только своё
  (`sender_id` = я). Удаление у обеих сторон.
- Удаление = `deleted_at = now()` (soft-delete; retention-purge уже вычищает
  такие строки физически). Выборки чата/треда/`room.snapshot` уже фильтруют по
  частичным индексам `deleted_at IS NULL` — проверить все SELECT'ы.
- Unread ЛС: удаление непрочитанного сообщения уменьшает счётчик получателя
  (событие ниже должно позволить клиенту пересчитать).

**Realtime:** `room.chat.deleted {roomId, messageId}` через `broadcast(room, …)`
+ preview-подписчикам; `dm.message.deleted {peerUserId, messageId}` через
`broadcastToUser` обеим сторонам.

**Клиент:** пункт «Удалить» на своём сообщении (hover/контекст-меню) в
`RoomChat` и `DmView`; для владельца комнаты — на любом сообщении комнаты;
обработка событий удаления (убрать из ленты, скорректировать unread).

**Тесты:** API — право удаления (гость/аккаунт/владелец/чужое → 403),
исчезновение из выборок и snapshot, unread после удаления; WS-события.

## 3. Модерация: кик и бан

**Миграция:** таблица `room_bans`:
`id varchar(36) PK`, `room_id` FK → rooms `ON DELETE CASCADE`,
`user_id varchar(36)` nullable FK → users `ON DELETE CASCADE`,
`ip text NOT NULL DEFAULT ''` (сырой, как `rooms.creator_ip`),
`created_at`, `expires_at timestamptz` nullable (задел, в 2.4.0 не читается),
`metadata jsonb`. Индексы: `(room_id, user_id)`, `(room_id, ip)`.
Лимит `MAX_ROOM_BANS` (env, default 100) — при переполнении 409 с внятной ошибкой.

**Присутствие:** при join/`handleState` запоминать IP пира в in-memory
presence (`getClientIp` уже есть) — источник IP для бана гостя.

**API (владелец комнаты, cookie-сессия, только статичные комнаты):**
- `POST /api/rooms/:roomId/kick {peerId}` — без записи.
- `POST /api/rooms/:roomId/ban {peerId}` → `{banId}`; запись `user_id`
  (accountUserId пира, если есть) + текущий IP пира; затем кик.
- `DELETE /api/rooms/:roomId/bans/:banId` — undo из тоста.

**Механика кика (общая для кика и бана):**
1. `RoomServiceClient.removeParticipant(livekitRoom, peerId)` из
   `livekit-server-sdk` (уже в зависимостях; учесть, что `LIVEKIT_URL` —
   `ws(s)://`, для RoomService нужен `http(s)://`-хост). Обязательно: токен
   живёт 6 ч (`LIVEKIT_TOKEN_TTL_SECONDS`), пассивного отказа в токене мало.
2. Инвалидация peer-сессии на сервере (state/token с этим `sessionToken` → 403).
3. Направленное WS-событие `room.kicked {roomId}` / `room.banned {roomId}`
   этому peer-соединению (+ `broadcastToUser`, если залогинен).

**Enforcement бана** (проверка `user_id` ИЛИ IP) на входных точках:
`handleState` (join/presence), `handleLiveKitToken`, `handleRoomChatPost`,
WS-подписка на room preview. Ответ — 403 с кодом `room_banned`.

**Клиент:**
- `ParticipantContextMenu`: для владельца статичной комнаты — «Исключить» и
  «Заблокировать» (видны только владельцу, не на себе).
- После бана у владельца — тост «N заблокирован» с кнопкой **«Отменить»**
  (окно ~10 сек; отмена дёргает `DELETE …/bans/:banId`).
- У цели — полноэкранный экран «Вас исключили из комнаты» / «Вы заблокированы
  в этой комнате» (по образцу `RoomEntryErrorScreen`), остановка реконнектов;
  те же экраны при 403 `room_banned` на входе.

**Тесты:** права (не-владелец → 403, временная комната → 403), бан гостя по IP
(новая peer-сессия с того же IP не входит), бан аккаунта (гостевой вход с того
же IP тоже блокирован), undo, cap, каскад при удалении комнаты, инвалидация
peer-сессии.

## 4. Web Push (инфраструктура)

**Зависимость API:** пакет `web-push`.

**Env:** `VAPID_PUBLIC_KEY`, `VAPID_PRIVATE_KEY`, `VAPID_SUBJECT`
(например `mailto:…`). Без ключей push выключен (как LiveKit: фича деградирует,
не падает).

**Миграция:** `push_subscriptions`:
`id PK`, `user_id` FK → users `ON DELETE CASCADE`, `endpoint text UNIQUE`,
`p256dh text`, `auth text`, `created_at`, `last_success_at`, `metadata jsonb`.

**API:**
- `GET /api/push/config` → `{enabled, vapidPublicKey}` (runtime, не в build).
- `POST /api/push/subscriptions {subscription}` — upsert по endpoint.
- `DELETE /api/push/subscriptions {endpoint}`.
- Отправитель `sendPushToUser(userId, payload)`: шлёт на все подписки
  пользователя; при 404/410 — удаляет подписку; уважает DND и mute (см. §6);
  поддерживает per-message TTL (для ring).

**Клиент:**
- Service worker — штатный SvelteKit `src/service-worker.ts`:
  - `push` → распарсить payload; **если есть window-клиент в фокусе — не
    показывать** (in-app тост уже покрыл), иначе `showNotification`.
  - `notificationclick` → сфокусировать существующую вкладку или открыть URL
    (`/r/<roomId>` для ring, лобби с открытым тредом для ЛС).
- Подписка/отписка + запрос разрешения — **только контекстно**: тумблер
  «Уведомления в этом браузере» в настройках; никакого запроса при загрузке.
- Payload-типы: `ring`, `dm.message`, `friend.request`, `friend.accepted`.

**Тесты:** API — CRUD подписок, чистка по 410, отсутствие ключей → `enabled:false`.
Отправку мокать (unit на выбор получателей/фильтры DND/mute).

## 5. Ring — «Позвать друга»

**API:** `POST /api/rooms/:roomId/ring {userId}` (cookie-сессия):
- отправитель — активный пир этой комнаты; получатель — его друг (`friendships`);
- кулдаун на пару отправитель→получатель: `RING_RATE_LIMIT` /
  `RING_RATE_WINDOW_MS` (env, default 1 за 30 сек) по образцу существующих
  лимитеров;
- доставка: `broadcastToUser(userId, {type:'ring.incoming', payload:{fromUser,
  room:{id,name,emoji}, expiresAt}})` + `sendPushToUser` с **TTL = окну ring**
  (`RING_TTL_MS`, default 30000), чтобы протухший зов не догнал позже;
- ответ отправителю всегда `{ok:true}` (кроме ошибок валидации) — судьба ring
  невидима.

**Клиент:**
- Кнопка «Позвать» в `RoomTopbar` (рядом со «Ссылкой»), только залогиненным:
  поповер со списком друзей (онлайн первыми, presence уже есть), клик → ring →
  тост «Приглашение отправлено».
- Входящий ring: глобальный тост (лобби и комната) «N зовёт вас в комнату X»
  с кнопками «Зайти» / «Отклонить», авто-скрытие по `expiresAt`; новый звуковой
  сигнал в `cues.ts` (`playRingCue`); «Отклонить» — локальное закрытие, без
  события отправителю.
- Клик по push-уведомлению — сразу в `/r/<roomId>`.

**Тесты:** не-друг → 403, не-участник комнаты → 403, кулдаун → 429,
WS-событие доставлено, TTL в push-вызове.

## 6. Настройки уведомлений

**Миграции:**
- `users`: + `dnd boolean NOT NULL DEFAULT false`.
- `dm_thread_mutes`: `user_id` FK, `peer_user_id` FK, `created_at`,
  UNIQUE `(user_id, peer_user_id)`, обе FK `ON DELETE CASCADE`.

**API:**
- `POST /api/notifications/settings {dnd}` / отдаётся в `GET /api/auth/me`.
- `POST /api/dm/:userId/mute`, `DELETE /api/dm/:userId/mute`; флаг `muted`
  в ответе `GET /api/dm/:userId`.
- `sendPushToUser`: не шлёт при `dnd`; для `dm.message` — не шлёт при mute треда.
  Ring при DND тоже гасится (DND = «не дёргай меня» без исключений).

**Клиент:**
- DND-тумблер в меню пользователя + индикатор на аватаре; состояние с сервера,
  клиент при DND глушит и звуковые сигналы (`cues.ts` читает общий стор).
- Mute треда ЛС: колокольчик в шапке `DmView`; глушит звук и push, unread-бейдж
  живёт.
- Mute комнаты: колокольчик в шапке чат-рейла (`RoomChat`); localStorage-ключ
  в стиле существующих (`voice-room:room-muted:<roomId>`); глушит
  `playRoomChatMessageCue` для этой комнаты.
- Вкладка «Уведомления» в `SettingsModal`: master-тумблер push этого браузера
  (подписка SW), DND, ссылка на существующую громкость сигналов.

**Тесты:** DND гасит push (unit на фильтр), mute треда гасит только свой тред,
`me`/`dm` отдают флаги.

## 7. Хоткей мьюта микрофона (веб)

- `Ctrl+Shift+M` (`⌘⇧M` на Mac) в комнате — toggle микрофона; игнорировать,
  когда фокус в текстовом поле. Существующий mic-cue и индикация уже есть.
- Реализация: слушатель на уровне room shell; вынести toggle из
  `controls.ts` в переиспользуемый вызов, если ещё не вынесен.
- Тест: обновление v2-ui-contract при необходимости; ручная проверка.

## Порядок работ и зависимости

1. **Чат-фундамент** (§1) — независим, можно первым/параллельно.
2. **Удаление сообщений** (§2) — миграции `author_user_id` + `deleted_at`.
3. **Модерация** (§3) — `room_bans`, LiveKit RoomService, enforcement, UI.
4. **Push-инфраструктура** (§4) — SW + подписки + VAPID; предпосылка для §5/§6.
5. **Ring** (§5) — использует §4 и `broadcastToUser`.
6. **Настройки уведомлений** (§6) — фильтры поверх §4; mute комнаты — независим.
7. **Хоткей** (§7) — в любой момент.

Каждый воркстрим — отдельная ветка/PR в `develop` (squash-merge), коммиты по
Conventional Commits, атомарно по сфере (api/web/тесты).

## Новые env-переменные

| Переменная | Default | Назначение |
| --- | --- | --- |
